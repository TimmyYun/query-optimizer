## Зачем

Equi-Width ставит границы «по линейке», EquiDepth — «по равной массе». Обе эвристики не знают,
**насколько неравномерны** данные внутри бакета. EntropyHist отвечает на вопрос: «если мне можно
поставить только B−1 разрезов, куда их поставить, чтобы внутри каждого бакета было
**как можно равномернее**?». Мера равномерности — энтропия. Это первый метод в курсе, где
построение — **оптимизация**, а не формула.

## Теория

### Распределение и энтропия

Данные = отсортированные различные значения `v_1 < … < v_n` с частотами `f_i` (по выборке).
Энтропия набора весов `w`:

```
H(w) = − Σ p_i log2 p_i,   p_i = w_i / Σ w
```

`H` максимальна (= `log2 d`) для равных весов и равна 0 для одного значения. Для бакета
«почти равномерен» ⟺ его энтропия близка к `log2 d`.

Быстро для отрезка `[s, e)` через префиксные суммы (**ключевой трюк урока**):

```
W = P1[e] − P1[s],    H = log2 W − (Plog[e] − Plog[s]) / W,    Plog = prefix(w · log2 w)
```

— энтропия любого отрезка за O(1), всех разрезов бакета — одной векторной операцией.

### Что именно делаем равномерным: частоты или «площадь»

- **ME(F)** — веса `w_i = f_i` (частоты значений);
- **ME(A)** — веса `w_i = f_i · spread_i`, `spread_i = v_{i+1} − v_i` (Poosala): учитывает и
  **пустоты между значениями**. Дефолт в эталоне — ME(A).

### Построение: жадный нисходящий best-cut (Algorithm 1)

```
один бакет [0, n) → куча кандидатов
пока бакетов < B:
    взять бакет с лучшим разрезом, разрезать, для двух детей посчитать их лучший разрез
```

Скор разреза `k` бакета `[s, e)` (ME, Algorithm 1): `W · (H_parent − (H_left + H_right))` —
минимизируем, т.е. разрез, после которого **сумма** энтропий детей максимальна. В статье сумма
**невзвешенная** — эталон делает так же; взвешенная — отдельная абляция.
Варианты MSE (§4.3.2) и MB (§4.3.3) используют тот же движок с другой стоимостью.
Ровно `min(B, n) − 1` разрезов, даже если выигрыш ≤ 0.

### Оценка

- бакет хранит `min_value, max_value, tuple_count, distinct_count`;
- диапазон — линейная интерполяция по `[min_value, max_value]` (непрерывная, как в статье);
- точечный `[v, v]` — `T_b / d_b` (Eq. 1, дефолт статьи);
- **между бакетами есть щели** (`max` одного < `min` следующего): значения там оцениваются в 0.

```python

def build(sample, mn, mx, total_rows, n_buckets, method="ME", me_input="area"): ...
# bucket_ranges = [(min_value, max_value), ...] — по значениям выборки, а не по домену
```

Шаги:
1. `values, counts = np.unique(sample, return_counts=True)`, веса для ME(A)/ME(F).
2. Класс префиксных моментов: `P1`, `Plog` (+ `P2, P3` для MSE).
3. `split_scores(s, e)` — скоры всех разрезов `k = s+1..e−1` векторно.
4. Куча `(score, −W, k, s, e)`; ничьи — детерминированно (меньший разрез, меньший `s`).
5. Бакеты, `predict` с масштабом `N / len(sample)`.

Проверь сложность: построение на 100k выборке должно занимать десятки мс, а не секунды.

## Ловушки

- `w · log2 w` при `w = 0` — `nan`; у нас веса > 0, но защити.
- Округление префиксов даёт `H < 0` на 1e−15 — обрезай до 0.
- **Щели между бакетами.** Запрос целиком в щели → 0 → q-error = истина. Это не баг реализации,
  это свойство статьи — но это решение, и его надо уметь защитить или изменить (абляция).
- `bucket_ranges` — значения выборки; не путай с границами домена.
