## Зачем

Собрать всё в одну картину, которую можно положить в диссертацию: какой метод, на каких данных,
при какой памяти и цене адаптации выигрывает — и **почему**, своими словами, с опорой на
эксперименты из уроков.

## Что сделать

1. **Все тесты зелёные** (кроме сознательно изменённого поведения — опиши его):
   ```bash
   poetry run python -m pytest tests/lessons -q
   poetry run ruff check estimators lessons tests
   ```
2. **Сводный статический прогон** — все методы, все 13 датасетов, 200k запросов:
   ```bash
   mkdir -p lessons/results
   for m in trivial equi_width tkhist equi_depth entropy_hist equi_hist st_hist hybrid; do
     poetry run python lessons/check/check_static.py $m --json lessons/results/static_$m.json
   done
   ```
   Плюс твоя лучшая конфигурация Hybrid (например, `--kw partition=equidepth parametric_only=true`).
3. **Сводный дрейф** — оба сценария, все методы, `--json lessons/results/drift_<scenario>_<m>.json`.
4. **Равная память** — для 3–4 ключевых датасетов прогони бейзлайны с памятью твоего лучшего
   Hybrid (урок 7, «Поиграть 4»).
5. Напиши небольшой скрипт `lessons/check/report.py`, который из `lessons/results/*.json`
   строит markdown-таблицы (медиана / P95, жирным — лучший; отдельно отметить методы, которые
   учатся на точных ответах: EquiHist, STHist).
6. **Перенос в основной пайплайн** (по желанию): `run_*.py` на `dev` переключить с `models/`
   на `estimators/` — интерфейс уже общий, раннерам нужен только адаптер.

## Итоговая таблица → `lessons/notes/10.md` и `lessons/README.md`

Заполни таблицу из README по своим заметкам 01–09. Для каждого метода — по одной строке:

- **что хранит** (и сколько чисел на `normal`);
- **на чём учится** (выборка / ответы запросов / ничего);
- **меняет ли границы**;
- **как адаптируется к дрейфу** и сколько это стоит;
- **где лучший** (датасет + ворклоад) и **где худший** — с объяснением механизма, а не только цифрой.

## Вопросы, на которые к концу курса должен быть ответ без подглядывания

1. Почему на `uniform` все сэмпловые методы упираются в ~1.04, а `trivial` — 1.004?
2. Почему узкие запросы — единственное место, где методы реально различаются?
3. Какой метод ты бы поставил в СУБД для колонки с «горячими» значениями? С кластерами? С гладким горбом?
4. В чём **именно** вклад Hybrid по сравнению с шестью бейзлайнами, и при каком условии он
   исчезает (равная память, широкие запросы, пустые бакеты)?
5. Почему STHist и EquiHist нельзя ставить в одну колонку «лучших» с сэмпловыми методами?
6. Почему под дрейфом Hybrid лучший по хвосту, но проигрывает по медиане методам с новыми границами?
7. Сколько стоит адаптация каждого метода и какие стадии раньше не замерялись?
