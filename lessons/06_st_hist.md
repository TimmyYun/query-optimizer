## Зачем

EquiHist (урок 5) учит **массу** бакетов, но сетка у него фиксированная. STHist идёт дальше:
**данные он не видит вообще** — ни `freq`, ни выборку. Старт — равномерная гистограмма из
одних метаданных (`N, min, max`). Всё остальное он узнаёт из ответов запросов, включая то,
**где ставить границы**: похожие соседние бакеты сливаются, освободившиеся «слоты» отдаются
тяжёлым бакетам, которые режутся мельче. Это вторая сторона спектра: «вообще без ANALYZE».

## Теория

### Инициализация (§3.1)

`B` бакетов равной ширины, у каждого `f = N / B`. Выборка не используется.

### Обновление частот (Fig. 2)

Для ответа `actual` на запрос `Q`:

```
est  = Σ_b w(Q,b) · f_b                       # w = доля бакета под запросом
err  = actual − est
f_b ← max(0, f_b + α · err · (w(Q,b) · f_b) / est)      для каждого перекрытого b, α = 0.5
```

Ошибка делится между бакетами **пропорционально их вкладу в оценку** (а не равномерно, как в
EquiHist). Нормировки `Σ f = N` нет — масса может дрейфовать, так в статье.

### Реструктуризация каждые R = 200 запросов (Fig. 3)

1. **Слияние**: жадно сливаем соседние «прогоны» бакетов с минимальным расстоянием
   `max |f_i − f_j|` (по **исходным** бакетам прогона), пока оно ≤ `m · N` (`m = 0.025%`).
2. **Разбиение**: освобождённые `F` слотов делятся между `s · B` (`s = 10%`) самыми тяжёлыми
   **неслитыми** бакетами пропорционально частоте; бакет с `a` слотами → `1 + a` равных частей,
   частота делится поровну.
3. Число бакетов `B` и полная масса **не меняются**.

Статья не фиксирует ряд мелочей (округление `s·B`, распределение остатка слотов, ничьи) —
их нужно решить и записать. Список таких решений эталона — в docstring `STHistogram`.

## Что написать

```python
def build(sample, mn, mx, total_rows, n_buckets, alpha=0.5, restructure_every=200,
          merge_threshold=0.00025, split_fraction=0.10) -> "STHist": ...   # sample игнорируется
def from_buckets(lows, highs, freqs, total_rows, **same_params) -> "STHist": ...  # для тестов

class STHist:
    bucket_ranges, bucket_freqs
    def predict(self, q) -> float
    def observe(self, q, actual) -> None      # Fig. 2 + каждые R вызовов restructure()
    def restructure(self) -> None             # Fig. 3
    def total_mass(self) -> float
```

Бакеты здесь **разной ширины** — индекс бакета через `bisect` по `lows`, не арифметикой.
Слияние: наивно O(B²) на реструктуризацию; эталон использует кучу с ленивой инвалидацией
(O(B log B)) — начни с наивного, ускорь, если `check_static` идёт дольше пары минут.

## Ловушки

- **`est == 0`**: формула делит на `est`. Статья не определяет — эталон пропускает обновление
  (событие `unlearnable_zero_estimate`). Бакет с `f = 0` навсегда «мёртв». Подумай, хорошо ли это.
- Расстояние между прогонами — по **исходным** частотам, не по суммам прогонов.
- После слияния и разбиения пересобери все массивы, иначе `predict` читает старую сетку.
- Используй **точный** ответ (без прижатия к 1) в `observe` — ответ 0 тоже информация.

## Вопросы для самопроверки

1. STHist «не смотрит на данные». Значит ли это, что он честнее сэмпловых методов? (Подумай,
   сколько точных ответов он получил за прогон — и сколько строк видит выборка.)
2. Почему ошибка делится пропорционально вкладу `w·f`, а не поровну?
3. Почему слияние идёт по максимуму разности частот, а не по разности сумм?
4. Чем STHist принципиально отличается от EquiHist, если оба учатся по фидбэку?
5. В какой реальной ситуации в СУБД STHist был бы правильным выбором?
