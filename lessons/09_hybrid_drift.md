## Зачем

У Hybrid под дрейфом устаревают **три** вещи: массы бакетов, форма внутри бакетов и сетка.
ANALYZE (как у Equi-Width) чинит только массы. Утверждение диссертации: остальное можно
чинить **дёшево и локально** — подстроить массы по ответам запросов (FT) и переобучить модели
только в тех бакетах, где они явно сломались (RB), не перестраивая всё.

Этот урок — ещё и ответ на вопрос «почему Equi-Width „пересобирается“ быстрее, чем наш метод,
хотя мы пересобираем только плохие бакеты». Разберись в нём до конца — его зададут на защите.

## Теория

### Стадии на каждом шаге

1. **refresh (ANALYZE)** — счётчики бакетов по новой выборке, модели формы остаются.
   Плюс сохранить новую `est_freq` — на ней будет учиться RB.
2. **FT — finetune массы** (`feedback_update`): для запросов с q-error > 1.2 истинная и
   предсказанная масса раскладываются по перекрытым бакетам пропорционально ширине перекрытия;
   для бакета `ratio = Σtrue / Σpred` (clip `[0.2, 5]`), `count ← count·(1 − α) + count·ratio·α`,
   `α = 0.15`. Модели не трогаются.
3. **Поиск плохих бакетов** (`detect_bad_buckets`): для каждого бакета — медиана q-error
   запросов, которые его задели; плохой, если запросов > 5 и медиана > 1.3.
4. **RB — rebuild**: переобучить каскад (урок 7) **только** в плохих бакетах на `est_freq` шага.

### Сколько это стоит (и почему Equi-Width «быстрее»)

Замер на `normal → zipf`, 1M запросов на шаг (старые раннеры):

| что | бакетов | время на шаг |
|---|---|---|
| Equi-Width «Build Time» | все 873 | **6–9 мс** |
| Hybrid RB | 130–420 | **1.0–3.4 с** |
| Hybrid FT | — | ~1.7 с |
| Hybrid `detect_bad_buckets` | — | ~1.5 с — **не замерялось вообще** |

1. **Цена одного бакета разная на 3–4 порядка.** Equi-Width: пересчёт бакета = одна разность
   префиксных сумм; весь ANALYZE = `bincount + cumsum` ≈ 7 мс. Hybrid RB на бакет: ~600
   обучающих точек (в эталоне — Python-объекты и ~150k скалярных `np.clip`), 500 валидационных
   запросов, 4–8 подгонок моделей → ~6 мс **на бакет**. Один бакет Hybrid ≈ весь ANALYZE Equi-Width.
2. **Equi-Width в дрейфе ничего не пересобирает** — сетка с шага 0, обновляются только счётчики.
   Его честная пара у Hybrid — `refresh`, а она в старом раннере не замерялась. RB — отдельная
   стадия, аналога которой у Equi-Width нет.
3. **RB почти ничего не даёт**: FT_Med → RB_Med меняется в 4-м знаке (1.1496 → 1.1491), кроме
   шага 5% (1.134 → 1.118). Почти вся точность — от ANALYZE и FT.

Правильная формулировка для диссертации: «адаптация Hybrid стоит X мс на шаг (refresh + FT +
detect + RB, все замерены) против Y мс ANALYZE у Equi-Width и даёт Z по точности» — с честными X и Y.

## Что написать

```python
class Hybrid:
    def refresh(self, sample, mn, mx, total_rows) -> None
    def adapt(self, queries, actual, sample, mn, mx, total_rows) -> dict
        # {"finetuned": n, "rebuilt": n, "t_ft": s, "t_detect": s, "t_rb": s}
```

`adapt` получает **только запросы фидбэка** (стенд оценивает на других). Возвращай время
каждой стадии — стенд положит их в вывод как `info_*`.

## Ловушки (найдено в эталоне)

1. **Нормировка CDF после FT.** FT меняет `b.count`, а `_collect_cdf_training_rows` делит массу
   выборки на этот изменённый `b.count` (`hybrid.py:331`). CDF перестаёт доходить до 1 (или
   обрезается), валидация умножает на тот же неверный `b.count`, а `predict` для правого края
   ставит 1.0 — модели после RB систематически смещены. Нормируй на массу **выборки** в бакете
   (урок 7, «на чём учиться»). Самопроверка: после обучения `|F(hi) − 1| < 0.02` для каждого бакета.
2. **Оживление мёртвого бакета** (`hybrid.py:144`): `new_count = true_m · α`, где `true_m` —
   **сумма** по всем плохим запросам шага (до сотен тысяч), а не среднее. Счётчик может превысить N.
3. **Атрибуция ошибки.** `detect_bad_buckets` приписывает q-error всего запроса **каждому**
   задетому бакету, включая внутренние, где модель вообще не используется. FT раскладывает
   массу по ширине перекрытия — то есть снова «равномерно»; на DSB с пиками FT поэтому
   **ухудшает** P95 (`EXPERIMENT_RESULTS.md` 7.4). Подумай, как делить по вкладу (как STHist, урок 6).
4. **In-sample оценка.** Старые раннеры считали FT/RB на тех же запросах, что ушли в фидбэк.
   Стенд урока оценивает на отложенной половине — сравни свои числа FT с числами из отчёта.
5. **Незамеренные стадии** — refresh и detect. Замеряй всё.
6. **Отчётный баг** (`run_hybrid_drift.py:264`): при 0 переобученных бакетов колонки `RB_*`
   показывают Shock, а не FT, хотя модель уже после FT.
7. **FT выбрасывается на следующем шаге**: `refresh` снова берёт счётчики из выборки. Это
   решение, а не ошибка — но тогда FT не накапливает знание между шагами. Альтернатива —
   хранить поправочный множитель бакета и применять его поверх ANALYZE.
8. **Инференс замедляется** (медиана 6 → 31 мкс с 30% сдвига): RB всё чаще выбирает деревья
   (80 → 256 бакетов), а `sklearn.predict` дорог. «Запекай» модели (урок 7, ловушка 6).
9. **Сетка с шага 0.** Голова `zipf` (значения 1–59) попадает в 1–2 бакета шириной ~1 100;
   модель внутри улучшает, но медиана застревает на ~1.17, пока EquiDepth/EntropyHist уходят
   к 1.000. «Hybrid умеет менять форму, но не границы».
